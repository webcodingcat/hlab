## 1. Go access to libvirt
- `libvirt.org/go/libvirt` v1.12009.0 (2026-11-09, tracks libvirt 12.9.0; releases roughly every 1-2 months, so maintained). cgo, needs `libvirt-dev` and links libvirt.so.0 dynamically. [V] https://gitlab.com/libvirt/libvirt-go-module/-/tags
  API has `BlockCopy`, `ManagedSave`, `SetBlockIoTune`/`GetBlockIoTune`, `UpdateDeviceFlags`, `GetAllDomainStats`, `NewConnect` [V] https://pkg.go.dev/libvirt.org/go/libvirt
- `github.com/digitalocean/go-libvirt`: NO tagged releases; latest pseudo-version v0.0.0-20261013170128-efbbdf578ac8 (2026-10-13; pkg.go.dev says a newer one may exist). Pure Go, speaks libvirt RPC over the unix socket (`/var/run/libvirt/libvirt-sock`), code generated from the libvirt protocol. README: "API is not considered stable", vendor/pin it. [V] https://github.com/digitalocean/go-libvirt
  Confirmed methods: `DomainBlockCopy(Dom, Path, Destxml, Params, Flags)`, `DomainAttachDeviceFlags`, `ConnectGetAllDomainStats`, `DomainBlockResize`, `DomainBlockJobAbort`, `ConnectDomainEventRegisterAny`. Arg types for DomainManagedSave, DomainSetBlockIOTune, DomainUpdateDeviceFlags, DomainOpenGraphicsFd exist (pkg.go.dev) [V]; since the code is generated from the full protocol, the methods exist too, but exact signatures not read.
- Static/cross build: only go-libvirt (pure Go) gives CGO_ENABLED=0 and a build of hlabd for linux from the Windows dev box (`task build` runs on Windows). The cgo module needs libvirt headers, so it must be built on Linux (CI).
- Recommendation: `digitalocean/go-libvirt`, pinned pseudo-version, wrapped behind the `platform` interface (the wrapper absorbs API churn). Pitfalls: manual event-loop handling (use ConnectDomainEventRegisterAny, reconnect on socket loss), connection needs root or libvirt group (hlabd is root, fine); typed params (`TypedParam`) are verbose for blkdeviotune/stats.
- VNC: define `<graphics type='vnc'>` listening on a unix socket (`<listen type='socket' socket='...'/>`) or 127.0.0.1 autoport, and have hlabd proxy it; get the endpoint from the live domain XML. [M]

## 2. Disks, firmware, save state
- qcow2: `qemu-img create -f qcow2 [-b base -F qcow2] child.qcow2 <size>` (package qemu-utils). Files must be reachable by libvirt-qemu; libvirt labels disks in the domain XML and its backing chain dynamically (AppArmor/DAC), so a data dir like /var/lib/hlab works. [M]
- Live resize: `DomainBlockResize` with BYTES flag, grow only. [M]
- Live crash-consistent copy: `BlockCopy` (dest `<disk type='file'><driver type='qcow2'/><source file=.../></disk>` XML), wait for the BLOCK_JOB_READY event, then `BlockJobAbort` WITHOUT the pivot flag = "finish": destination is a faithful copy of the moment of the abort. On a persistent domain the TRANSIENT_JOB flag is needed ("lifts the restriction of copy jobs to transient domains", virsh `blockcopy --transient-job`). Copy is full (flattened) unless SHALLOW. https://libvirt.org/manpages/virsh.html [V for flags, rest M]. Alternative (more steps): external disk-only snapshot + blockcommit.
- blkdeviotune: `SetBlockIoTune(disk, params, flags)`; LIVE for running, CONFIG for persistent; setting one value of a category (bytes/iops/size) resets the other two of that category to unlimited, 0 clears. [V] same page.
- Disk identity (Hetzner `/dev/disk/by-id/scsi-0HC_Volume_<id>`): use virtio-scsi (`<controller type='scsi' model='virtio-scsi' index='0'/>`, disk `<target bus='scsi'/>` with `<address type='drive' controller='0' bus='0' target='0' unit='N'/>`; drive address is documented, unit is a number up to 20 digits [V], https://libvirt.org/formatdomain.html) and per disk `<vendor>HC</vendor><product>Volume</product><serial><id></serial>` (vendor max 8 bytes, product max 16) [M]. Expected guest link `scsi-0<vendor>_<product>_<serial>` as `scsi-0QEMU_QEMU_HARDDISK_<serial>` is for QEMU defaults; NOT verified that the "0" form comes out - test in a booted guest. `<wwn>` adds page 0x83 NAA id and links `wwn-0x...`/`scsi-3...`. virtio-blk does NOT give scsi- links.
- CD-ROM: `<disk device='cdrom'>` on a SCSI/SATA bus; insert/eject on a running domain = `UpdateDeviceFlags` with the full disk XML with/without `<source>`, flags LIVE|CONFIG (what `virsh change-media` does). [M]
- Boot order: per-device `<boot order='N'/>`; cannot be mixed with `<os><boot dev=.../>`. [V]
- UEFI/Secure Boot: `<os firmware='efi'>` + `<firmware><feature enabled='yes' name='enrolled-keys'/><feature enabled='yes' name='secure-boot'/></firmware>` and `<loader secure='yes'/>` (autoselection since libvirt 7.2.0 [V] https://libvirt.org/formatdomain.html). Needs package `ovmf` (ships the descriptor JSONs in /usr/share/qemu/firmware) [M]; check with `domcapabilities` which combination is offered on each distro. Needs `<smm state='on'/>` and q35 machine for secure boot [M]. Debian/Ubuntu guests need the MS keys enrolled (enrolled-keys yes). NVRAM per VM is created by libvirt; remove with `UNDEFINE_NVRAM` flag.
- Save state: `ManagedSave`; the next `Create`/start restores it automatically; `HasManagedSaveImage`, `ManagedSaveRemove` to discard. libvirt-guests.service: default `ON_SHUTDOWN=suspend` = managedsave of running guests at host shutdown; `shutdown` mode has SHUTDOWN_TIMEOUT 300 s; no per-guest ordering. [V] https://libvirt.org/manpages/libvirt-guests.html . Not verified: whether libvirt-guests is enabled by default in Debian/Ubuntu. Do not rely on it: hlabd should save/stop its VMs itself in its stop path (see 5).

## 3. Host networking
- Isolation: Linux bridge port flag `isolated on` (kernel feature): isolated ports cannot talk to each other, only to non-isolated ports; appliance port stays non-isolated = exact analog of private VLAN. No VLAN filtering needed. vishvananda/netlink v1.3.1 has `LinkSetIsolated(link, bool)`, `BridgeSetVlanFiltering`, `BridgeSetMcastSnoop` [V] https://raw.githubusercontent.com/vishvananda/netlink/v1.3.1/link_linux.go . libvirt also has `<port isolated='yes'/>` in `<interface>` [M, since 6.1.0], which sets it at VM start; for hot-plugged NICs the same XML applies. hlabd should still re-verify the flag.
- MAC deny / spoofing / DHCP / RA guards: own nftables table in the `bridge` family (hook forward, rules on `iifname`/`ether saddr`, `udp sport 67` and `icmpv6 type nd-router-advert` dropped unless from the appliance port). google/nftables v0.3.0 supports bridge family tables [M]. Do not use libvirt nwfilter: it is ebtables/iptables based and libvirt's nftables move did not cover it as of the sources found [partly V: https://fedoraproject.org/wiki/Changes/LibvirtVirtualNetworkNFTables]. vnet device names are dynamic: set `<target dev='hlab-<id>'/>` in the NIC XML (libvirt accepts names not starting with vnet) so rules can match stable names.
- Host routes, bridge creation, addresses: netlink is enough. Routes via the bridge disappear when the bridge is deleted.
- IPv4 forwarding: write /proc/sys/net/ipv4/ip_forward (also per-interface `conf/<if>/forwarding`); not persistent, hlabd sets it at start.
- Masquerade: nftables `ip hlab` table, nat postrouting chain; enough with google/nftables.
- Docker: when Docker enables forwarding (iptables backend, default) it sets FORWARD policy DROP; opt-out is `ip-forward-no-drop` [V] https://docs.docker.com/engine/network/packet-filtering-firewalls/. Docker 29 nftables backend is experimental, opt-in, does not enable IP forwarding itself [V] same page. KEY POINT [M, nftables semantics]: with iptables-nft the DROP policy lives in table `ip filter` chain FORWARD; an accept in hlab's own nft base chain does NOT override a drop in another base chain on the same hook. Only host-originated traffic (host program -> VM, OUTPUT/INPUT) is unaffected; VM egress to internet passes FORWARD. So: at start, if `iptables`/DOCKER-USER exists, insert `-I DOCKER-USER -i <br> -j ACCEPT` and `-o <br> -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT` (the documented user hook; Docker keeps DOCKER-USER), remove them at stop; if the Docker nft backend is used, check its tables in a test VM (unclear). Needs a test VM with Docker installed - UNCONFIRMED end to end.
- ufw: default forward policy DROP; needs `ufw route allow in on <br>` / `out on <br>` (or equivalent) [M]. firewalld (not default on Ubuntu/Debian): bridge lands in default zone; add the interface to `trusted` zone at runtime [M]. Plan: detect and add runtime-only rules; document; prefer rules over disabling anything.
- Are netlink v1.3.1 and nftables v0.3.0 enough on the host? Yes for bridge, isolated, routes, sysctl via /proc, nftables incl. bridge family. The only external call is iptables for DOCKER-USER (or use the nftables lib to edit `ip filter` DOCKER-USER, fragile because of iptables-nft compat expressions: prefer the iptables binary).

## 4. systemd-resolved
- D-Bus `org.freedesktop.resolve1.Manager`: `SetLinkDNS(ifindex i, addresses a(iay))`, `SetLinkDomains(ifindex i, domains a(sb))` where bool=true means routing-only (`~zone`), also `SetLinkDefaultRoute`, `RevertLink`. Runtime state, per link; dropped when the link is deleted [M, resolve1 D-Bus docs https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.resolve1.html]. Reverse zones: domain `~<a.b.c>.in-addr.arpa` in the same call. Caller root passes polkit.
- godbus/dbus v5.2.4 (2026-10-13) [V]. coreos/go-systemd v22.7.0 (2026-01-27) [V].
- Set at start, `RevertLink` at stop. Resolved restart loses runtime settings: subscribe to `NameOwnerChanged` for org.freedesktop.resolve1 and reapply. [M]
- Debian 13: `systemd-resolved` is a separate package, not installed by default; installing it takes over /etc/resolv.conf (stub symlink) and may change the host's DNS setup. Not verified (postinst could not be fetched). Recommendation: `Recommends: systemd-resolved`, hlabd checks that resolve1 is on the bus and /etc/resolv.conf points to the stub (127.0.0.53), otherwise reports a clear message. Ubuntu 24.04/26.04 have it by default.

## 5. systemd, polkit, socket
- Unit: no `[Install]` section (never started at boot), `Type=notify`, `Wants=libvirtd.service` + `After=libvirtd.service` (stop happens in reverse order = hlabd stops before libvirtd, so it can managedsave VMs), `TimeoutStopSec` large (save of RAM), `RuntimeDirectory=hlab`. QEMU processes live under libvirt's machine.slice, so stopping hlabd does not kill them. [M]
- sd_notify: `daemon.SdNotify(false, daemon.SdNotifyReady)` from go-systemd v22.7.0 `daemon` package; no cgo needed.
- Start/stop from Go: `github.com/coreos/go-systemd/v22/dbus` `StartUnitContext(ctx, "hlabd.service", "replace", ch)` (uses godbus; system bus). Alternative `systemctl start` via exec; both hit the same polkit action.
- Polkit rule (JS) in `/usr/share/polkit-1/rules.d/50-hlab.rules` (packaged; polkitd reloads rules by itself) [M]:
  `polkit.addRule(function(a, s){ if (a.id=="org.freedesktop.systemd1.manage-units" && a.lookup("unit")=="hlabd.service" && ["start","stop","restart"].indexOf(a.lookup("verb"))>=0 && s.isInGroup("hlab")) return polkit.Result.YES; });`
  Polkit 124/127 (Ubuntu) still use JS rules; `.pkla` is gone. Pitfall: the rule must not match other units; `verb` values are start/stop/restart/reload/kill... Test with a non-session (ssh) login too.
- Socket: create `/run/hlab/hlab.sock` yourself in hlabd (a systemd .socket unit would be started at boot, which we do not want), umask 007 or chown to group `hlab` (look up the gid), mode 0660; directory 0750 root:hlab. Optionally check peer with SO_PEERCRED. The socket vanishes when hlabd stops, so the CLI must handle "not running" itself (start via D-Bus, then wait for the socket with a deadline).

## 7. CA trust
- `/usr/local/share/ca-certificates/<name>.crt` (must be `.crt`, PEM) then `update-ca-certificates` (removal: delete file, `update-ca-certificates --fresh`). Covers curl, Go, OpenSSL, Python, git; Java via ca-certificates-java hook; Node needs `NODE_EXTRA_CA_CERTS`. [M]
- Browsers: Firefox uses its own store (deb/ESR: policies `Certificates.ImportEnterpriseRoots` or `Install` in `distribution/policies.json`; Ubuntu's Firefox is a snap, system roots handling unverified). Chrome/Chromium on Linux use the NSS db `~/.pki/nssdb` per user (`certutil -d sql:$HOME/.pki/nssdb -A ...`); snap Chromium has its own sandboxed db. [M, not verified today]. Recommendation: system store in postinst/at `hlab` trust command; browsers as documented per-user step or best effort.

## 8. Packaging
- nfpm v2.49.0 (2026-11-12) [V https://github.com/goreleaser/nfpm/releases]. Config: `scripts: {preinstall, postinstall, preremove, postremove}`, `deb.scripts.rules/templates/config`, `contents` types `config`, `dir`, `symlink`, `depends`/`recommends` (per-format via `overrides.deb`), `deb.fields`; no templating, env var expansion in selected fields only [V https://nfpm.goreleaser.com/docs/configuration/]. nfpm does not say what argument postrm gets; that is dpkg: maintainer scripts get `$1` = `remove|purge|upgrade|...` (postrm), `remove|upgrade|deconfigure` (prerm) [M, Debian Policy 6.5].
- Scripts: prerm `remove`: stop hlabd, run the cleanup (VMs, bridge, routes, resolved link, nft/iptables rules, CA file) - not on `upgrade` (restart instead if it was running). postrm `purge`: delete /var/lib/hlab and logs, `delgroup hlab`, remove CA; `remove` keeps data. Files marked `config` under /etc are removed by dpkg on purge; data under /var/lib need the script. postrm must use only essential tools (no hlab binary). postinst: `addgroup --system hlab`, `systemctl daemon-reload`, add `$SUDO_USER` to `hlab` if set, otherwise print instruction; membership needs a new login. Never enable the unit.
- Depends (proposed): `systemd`, `polkitd`, `libvirt-daemon-system`, `qemu-system-x86`, `qemu-utils`, `ovmf`, `libgtk-4-1`, `libwebkitgtk-6.0-4`, `nftables`, `ca-certificates`. Recommends: `systemd-resolved`, `gnome-shell-extension-appindicator`, `iptables` (for DOCKER-USER). Package names [M]: check each exists in noble, resolute and trixie (`apt-cache policy` in containers) in CI.
- Compression: dpkg on 24.04/Debian 13 handles zstd; default gzip is safest. One .deb for all three targets: build on `ubuntu-24.04` so glibc (2.39) is the oldest.

## Summary of recommendations
1. libvirt: digitalocean/go-libvirt (pure Go, static, cross-buildable), pinned pseudo-version, behind `platform`.
2. VM disk model: virtio-scsi, vendor `HC` / product `Volume` / serial `<id>`; blockcopy + finish for live copy; managedsave done by hlabd itself.
3. Isolation via bridge `isolated` flag; guards via an own nftables bridge table; no nwfilter, no VLANs.
4. Docker/ufw/firewalld: explicit accept rules (DOCKER-USER via iptables, `ufw route`, trusted zone) added at start, removed at stop; needs a real test.
5. resolved via D-Bus, runtime settings reapplied on name-owner change; systemd-resolved as Recommends with a runtime check.
6. polkit JS rule for exactly `hlabd.service` + group `hlab`; unit with no [Install], After/Wants libvirtd; own socket 0660 root:hlab.
7. Wails default GTK4/WebKitGTK 6.0 (no gtk3 tag); cgo build on Linux CI; tray tests: Chromium + stubbed runtime (spike needed).
8. nfpm v2.49.0, build on ubuntu-24.04, scripts branch on `$1`.

Unclear / needs a spike: exact guest by-id naming for HC volumes; Docker nft-backend interplay; Debian 13 systemd-resolved postinst behaviour; AppIndicator on GNOME 50 with Wails; Playwright alternative; Wails GTK4 build on the runner; libvirt-guests default enablement; browser CA behaviour for snap packages.
