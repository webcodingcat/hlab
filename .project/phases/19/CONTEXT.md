# Phase 19 context

Confirmed assumptions and answers from the start of the phase (2026-11-22/23).

- Addresses: `transit.Addrs.Storage` (broadcast minus 2 of the public range, default `198.19.255.253`) and `StorageAgent` (`Storage:9100`); `ipam.NextPublic` never hands out that address.
- Storage VM `<tag>-storage`: Debian 13 generic, 2 vCPU, 1024 MB, 10 GB system disk copied from the base image, fixed MAC `02:48:4c:00:00:03` on the public PVLAN as an isolated guest port; own cidata (agent role `storage`, kv `storage.secret`, packages from `catalog/storage-debs.json`); follows `stop_behaviour`.
- Data disk `<data>\storage\data.vhdx`: dynamic, 64 TiB nominal (RESEARCH 9), `mkfs.btrfs -K` only when it holds no filesystem, mounted with `discard=async`; full qgroups as in E18, not squota (decision, cost medium).
- Lifecycle: the first `create_storage_box` creates the VM; the delete of the last box removes the VM and `storage\`; cloud start powers it on when boxes exist and pushes `agentapi.Storage` with retries; box actions wait for the agent with their own deadline (about 5 min for the first create); cloud stop stops the storage VM before the appliance.
- Compaction: after the storage VM is off at a cloud stop, hlabd runs `Optimize-VHD -Mode Full` on data.vhdx (new platform method `CompactDisk`); a failure is logged and the stop continues; skipped (logged) with stop_behaviour `save` and at a Windows shutdown.
- Free space: before `create_storage_box` and `change_type` to a larger type hlabd reads the free bytes of the host drive of the data folder (`windows.GetDiskFreeSpaceEx`, injectable) and answers 412 `resource_unavailable` below a fixed reserve of 10 GiB (decision with DECISIONS.md entry, cost low; named in deviations.md).
- Rejected: one image file per box (host/VM coordination at create and delete, shrinking at change_type); DECISIONS.md, cost medium.
- `storage-debs.json`: the seven packages of RESEARCH 1.2 (btrfs-progs, liblzo2-2, libreiserfscore0t64, rsync, borgbackup, python3-msgpack, python3-packaging) in the format of `appliance-debs.json`; the implementer recomputes every SHA-256 before committing; one `dpkg -i`, `rsync.service` disabled. Samba, Apache, vsftpd come in phase 20.
- Storage agent (`hlab-agent --role storage`): idempotent `PUT /v1/storage` (UID `n`, subvolume plus level-1 qgroup limited to the type size, chroot per account, crypt hash via `usermod -p`; boxes missing from the document are deleted); `POST /v1/jobs` serves `folders` and `usage`.
- sshd: port 22 always on, internal-sftp chrooted, read-write for the box and for subaccounts with write access, `-R` only for read-only subaccounts. Port 23 only with ssh_enabled (box, or the subaccount's own): sftp, strictly parsed scp, `rrsync [-ro]`, `borg serve --restrict-to-path` (`--remote-path` borg-1.1/1.2/1.4 accepted, all borg 1.4); Hetzner's other port 23 commands are not offered (deviations.md).
- SSH keys: API `ssh_keys` written once at create as OpenSSH lines into `<box home>/.ssh/authorized_keys`, never overwritten later; subaccounts use their own home's file; an `AuthorizedKeysCommand` helper accepts OpenSSH lines and RFC4716 blocks on both ports. Missing subaccount homes are created, owned by the box UID.
- Network: `agentapi.Access` gets `ReachableExternally`; appliance document `Config.Storage` and `Config.StorageBoxes`; box IPs routed onlink /32 via `Addrs.Storage`; DNS `u<n>` and `u<n>-sub<m>` under `storagebox.hetzner.internal`; isolation backstop lists the storage MAC; traffic from host/WSL2 (sources outside the public range plus the transit /30) to a box IP is dropped unless reachable externally; for subaccounts sshd `Match Address`.
- Create: `_hlab.n` and new `_hlab.ip` assigned in the create transaction; the API shows `username`, `server`, `system` null until active.
- Failed or interrupted `create_storage_box` (Recover at next start): the box is deleted and its IP released, the action carries the error. User decision; DECISIONS.md entry.
- Delete (user correction): the box is marked `_hlab.deleting`; Apply pushes a document without marked boxes; only after the agent confirmed does `done` delete records and release the IP; on agent failure the mark is cleared and the action fails with the error. For the last box hlabd deletes VM and `storage\` instead of pushing an empty document, then `done`. The action never reports success before the agent confirmed.
- Not active: subaccount create and every action except delete, `folders` included, answer 423 `locked` on a box that is not `active` (settles the backlog item).
- Folders: default `.`, direct subdirectories incl. hidden, sorted; 404 `not_found` for a missing path; 422 `invalid_input` (field `path`) for absolute or `..`; deviations.md names it as hlab's choice.
- Stats: change_type takes usage live from the agent (`usage` job), 422 `invalid_input` (field `storage_box_type`) when data exceed the new size; `stats` refreshed by a scheduler job every 5 min and after each box action; unit tests use the scheduler's test clock; no test waits for the tick.
- Quota error: as btrfs reports it (EDQUOT; SFTP SSH_FX_FAILURE).
- SBOX-21 (user answer): own storage box types in `%ProgramData%\hlab\storage-box-types.custom.json`, built like `server-types.custom.json` (JSON array of Hetzner `storage_box_type` objects, IDs from 100000, hlabd creates it as `[]` with the settings.toml ACL, problem `custom_storage_box_types`, reloaded by `POST /mgmt/v1/settings/reload`); unit level. The tray view is UI-14 in phase 21, not here.
- e2e rows, all on one shared box with reachable_externally on, except where noted: SBOX-03 host sftp/scp on port 22 with password and key; SBOX-13 WSL2 rsync, borg, sftp, scp on port 23, and port 23 closed with ssh_enabled off; SBOX-12 subaccount sees only its home, read-only writes nothing over 22 or 23; SBOX-11 folders created over SFTP appear in `folders`; SBOX-06 with own types of 64 MiB and 128 MiB: writing over the quota fails, change_type from the 128 MiB type to the 64 MiB type is refused while more than 64 MiB are stored (real data); SBOX-04 positive from `sharedServer`, negative from host and WSL2 against a second box without reachable_externally.
- SBOX-06 e2e setup without elevation: the test (as the interactive user) writes `%ProgramData%\hlab-dev\storage-box-types.custom.json` (ACL Interactive Users modify), calls `POST /mgmt/v1/settings/reload`, and restores the file afterwards.
- SBOX-08: `uninstall.ProfileVM` also matches `<tag>-storage`; `hlabDirs` gets `storage`; box data stay only with `--keep-data`.
- Manual check in CHECKS.md: write 2 GB into a box, delete the box, stop the cloud, compare the size of data.vhdx before and after.
- Documentation: guide.md (SSH access, subaccounts, folders); deviations.md (credentials of one box at another box's address, names under `storagebox.hetzner.internal`, failed create deletes the box, 423 on non-active boxes, quota check of change_type, free-space reserve, port 23 command set, folders behaviour; limit now about 250 lines, Q21); configuration.md (`storage-debs.json`, `storage-box-types.custom.json`, the `storage` and `cache` folders); api-coverage.md (`folders` served, snapshots until phase 20).
- Q21 settled: SPEC.md D4 about 250 lines.
